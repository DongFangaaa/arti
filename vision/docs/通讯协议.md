# 视觉 ↔ PLC 通讯协议（Modbus TCP 主路径）

## 0. 概述

| 项 | 值 |
|---|---|
| 主协议 | **Modbus TCP**（赛题 PDF 第 5 页："视觉相机采用 TCP 协议通讯"） |
| 备选协议 | Modbus UDP |
| 触发方向 | **PLC → Vision**（PLC 主动） |
| 上报方向 | **Vision → PLC**（Vision 被动） |
| 通讯介质 | TCP（容器内 → 容器外 PLC Modbus Server） |
| 报文频率 | 每工件 1 次（5 分钟内 12 工件） |

## 1. 主路径：Modbus TCP

### 1.1 寄存器映射

| 寄存器 | 类型 | 方向 | 默认值 | 说明 |
|--------|------|------|-------|------|
| **100** | Holding Reg (INT) | PLC→Vision | 0 | **xVisionTrigger**（0/1） |
| **110** | Holding Reg (INT) | Vision→PLC | -1 | **xDefectClass**（0=scratch, 1=stain, 2=chip, 3=hole, -1=未识别） |
| **111** | Holding Reg (INT) | Vision→PLC | 0 | **fConfidence**（0~1000，乘1000） |
| **112** | Holding Reg (INT) | Vision→PLC | 0 | **xResultValid**（0/1） |
| **113** | Holding Reg (INT) | Vision→PLC | 0 | **iResultSeq**（序列号，PLC 端可校验） |

**寄存器地址可在 `vision/config.yaml` 中调整**：
```yaml
plc:
  protocol: "modbus_tcp"
  modbus_tcp:
    registers:
      trigger: 100
      defect_class: 110
      confidence: 111
      valid: 112
      seq: 113
```

### 1.2 PLC 端配置（PLCnext Engineer）

PLCnext 需要：
1. 在 `MAIN` 程序中定义 5 个 INT 变量（`xVisionTrigger` 等）
2. 启用 Modbus TCP Server（端口 502），从站号 unit_id=1
3. 把这 5 个变量映射到 HR 寄存器 100~113

**OPC UA / Modbus 在 PLCnext 中是可选集成**——通过 `Arp.Plc.Eclr` 程序框架，或用 `pms-protocols-modbus` 库。

### 1.3 时序

```
PLC                                          Vision (Python Container)
 │                                                    │
 │ (物料到达, 触发拍照)                                 │
 ├─── HR[100] = 1 ──────────────────────────────▶│ read_trigger() → True
 │                                                    │ 抓帧
 │                                                    │ 预处理
 │                                                    │ 模型推理
 │                                                    │ 转换为 defect_id
 │                                                    │
 │                                                    │ write_result() →
 │ ◀── HR[110] = 3 ──────────────────────────────────│ (defect, conf, valid, seq)
 │ ◀── HR[111] = 920 ────────────────────────────────┤
 │ ◀── HR[112] = 1 ──────────────────────────────────┤
 │ ◀── HR[113] = 42 ─────────────────────────────────┤
 │                                                    │
 │ (PLC 程序读取 4 个寄存器, 控制三轴)                │
 │ ...                                                │
```

### 1.4 容错约定

| 场景 | vision 行为 | PLC 应处理 |
|------|-------------|-----------|
| 正常 | `valid=1`, `seq=N`, `class=0~3` | 读取后搬运 |
| 相机故障 | `valid=0`, `class=-1` | 报警停机 |
| 推理超时 | `valid=0`, `class=-1` | 报警停机 |
| 低置信度 | `valid=0`, `class=-1` | 报警停机 |
| Modbus 断开 | 持续重连，不上报 | 等待 N 秒无响应则报警 |

## 2. 协议切换（备用）

```yaml
# vision/config.yaml
plc:
  protocol: "modbus_udp"   # 切到 UDP（仅 protocol 改这里即可）
```

## 4. 容器网络

Podman 容器与 PLC 之间的网络：

```
容器（Podman）─── host 网络 ───▶ 宿主机 EPC
                                └──▶ Modbus TCP Server（PLC 进程内）
```

**推荐启动方式**（直接用 host 网络，避免端口映射问题）：

```bash
podman run --network=host -d --restart=always \
    --name vision \
    -e USE_DUMMY_CAMERA=0 \
    -v /opt/mvs_sdk:/opt/mvs_sdk:ro \
    localhost/vision:2.3
```

## 5. 答辩要点

| 问题 | 答案 |
|------|------|
| "为什么用 Modbus TCP？" | 赛题要求 TCP 协议；Modbus 是工业标准，PLCnext 原生支持 |
| "为什么不用 OPC UA？" | 赛题明确说 TCP 协议 |
| "为什么有 UDP fallback？" | 某些嵌入式场景 UDP 更轻量；现场可 30 秒切换 |
| "序列号 seq 有什么用？" | PLC 端可校验是否丢包/重发 |
| "valid=0 时 PLC 怎么办？" | 报警停机，宁可报错不可放错 |
